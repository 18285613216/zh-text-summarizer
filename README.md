# 中文长文本摘要 + 关键词提取器

一个只用 Python 标准库实现、无需训练的中文长文本工具：输入一篇中文新闻/通知/文章，输出 **3 句摘要 + 5 个关键词 + 压缩率**，并附带可复现的人工标注评测。

## 项目背景与要解决的问题

中文长文本（通知、新闻、政策解读、科普文章）在日常阅读和办公中非常常见，但完整读完往往需要几分钟。通用的做法有两种：一是直接用大模型生成式改写，成本高且结果不稳定；二是用第三方分词库 + TextRank 做抽取式摘要，但部署时常常卡在依赖安装上。

这个项目要回答一个具体问题：**在不安装任何第三方包、不训练模型的前提下，只用字符级统计和图的排序，能不能得到一份可用的中文摘要？** 项目里的分句、TF-IDF、余弦相似度、TextRank、关键词 PageRank 和评测指标全部手写实现，只依赖 `re`、`math`、`json`、`argparse`、`sys`、`os`、`collections`，在 Windows 上直接 `python main.py` 即可运行。

## 技术方法

核心是两张图 + 两个排序过程（全部手写，不调用任何 NLP 库）：

- **句子图（TextRank）**：先把长文按 `。！？；` 和换行切成句子，过滤去标点后不足 8 字的句子；每句用**字符 2-gram 词袋 + TF-IDF** 表示（idf 由本句集合内的句子频次自己算），句子相似度取**余弦**。以句子为节点、相似度大于 0 为边建图，边权即相似度；然后按 TextRank 公式 `WS(Vi) = (1-d) + d * Σ (w_ji / Σw_jk) * WS(Vj)` 迭代，阻尼 `d=0.85`，最多 50 次或相邻两轮最大变化 < `1e-4` 时停止。最后取权重 Top-3，按原文顺序输出。
- **关键词图（PageRank）**：以**字符 2-gram** 为节点，同一句中起点相距不超过 5 个字的 bigram 连边（窗口 = 5），边权为共现次数；跑带权 PageRank 后按分数排序。排序前用自建的 44 条停用字/词表过滤（的、了、是、我们、这个、可以……），再把原文中相邻的高分 bigram 合并成更完整的词（例如 `人工` + `工智` + `智能` → `人工智能`），输出 Top-5 并归一化权重。
- **评测**：①关键句命中率——摘要句与标注句的字符 bigram 余弦 ≥ 0.6 即算命中；②ROUGE-1——字符级 unigram 重合，报告 precision / recall / F1；③压缩率——摘要去标点字数 / 原文去标点字数。

## 快速开始

环境：Python 3.8+，**不需要安装任何第三方包**（Windows 控制台已做 UTF-8 处理）。

```bash
cd zh-text-summarizer

# 1) 在 3 篇示例上跑评测：每篇指标 + 平均值
python main.py --eval

# 2) 效果演示：打印 sample1 原文、摘要、关键词
python main.py --demo

# 3) 对任意中文文本文件生成摘要与关键词
python main.py --summarize data/sample2.txt
```

输出示例（`--demo` 的摘要部分）：

```text
摘要（3 句，按原文顺序）：
  1. 为帮助同学们系统了解人工智能技术、提升动手实践能力……
  2. 本期训练营由计算机学院承办……
  3. 请有意向的同学于 12 月 31 日 24 点前将报名表发送至……
关键词（Top-5，权重已归一化）：训练营(0.295) | 报名(0.234) | 人工智能(0.176) | 创新(0.153) | 同学(0.142)
```

## 实测结果

以下数字全部来自在本机实际运行 `python main.py --eval` 的输出，评测文本为 `data/` 下 3 篇自建示例，gold 为人工标注。

| 文本 | 关键句命中率 | ROUGE-1 F1 | 压缩率 |
| --- | --- | --- | --- |
| sample1.txt（校园 AI 训练营招募通知） | 0.667（2/3） | 0.804 | 0.308 |
| sample2.txt（垃圾分类政策解读） | 0.667（2/3） | 0.806 | 0.305 |
| sample3.txt（大语言模型科普） | 0.333（1/3） | 0.470 | 0.179 |
| **平均值** | **0.556** | **0.693** | **0.264** |

平均 ROUGE-1 的 precision / recall 分别为 **0.670 / 0.719**。3 篇平均每篇原文约 569 字、摘要约 149 字。命中率整体在 0.556，压缩率稳定在 0.15–0.35 区间内；sample3 的摘要只命中了 1 条标注句，原因见“局限与改进”。

sample1、sample2 的 ROUGE-1 F1 偏高（0.80 左右），是因为人工标注的关键句恰好被 TextRank 完整选中（相似度 1.000），属于 3 篇小样本下的巧合；sample3 则明显低于均值，说明这套方法对“段落间用词差异大”的科普文不够稳定。

> 示例文本与标注均为本人自建，3 篇规模，指标仅供参考。

## 局限与改进

**当前局限**

1. **抽取式不能改写。** 摘要只能从原文挑句子，无法合并、压缩或重写信息；当关键信息分散在多句里时，摘要会显得冗余或漏点（sample3 就漏掉了“数据偏见”和“使用风险”两段）。
2. **压缩率由句数而非字数控制。** 固定输出 3 句，遇到长句压缩率就偏高、短句就偏低，无法按“压缩到 20%”这样的目标精确控制篇幅。
3. **长句权重偏高，句子长度没有归一化。** 相似度基于 bigram 重叠，长句与其它句子的交集更多，容易在图上拿到高权重；个别极短句又可能因为向量稀疏、与少数句子相似度集中而得分虚高。长度因素没有显式建模，会带来选句偏差。
4. **字符 bigram 没有词边界。** 会出现 `工智`、`练营` 这类“碎词”，目前靠“相邻高分 bigram 合并”缓解，但没有真正分词；关键词窗口 5 和停用表也是人工设定，换领域需要重新调。
5. **评测规模很小。** 只有 3 篇、gold 只有 3 条关键句，且标注带有个人判断，指标波动大，不能当作通用 benchmark。

**改进方向**

- **TextRank + MMR**：在选句时加入最大边际相关性（Maximal Marginal Relevance），惩罚与已选句子高度相似的候选，减少摘要冗余。
- **按字数预算选句**：把“取 Top-3”改成“在目标字数内做背包式选择”，让压缩率可控。
- **接大模型做生成式摘要**：用大模型对抽取出的关键句做融合改写，解决“不能改写”和“信息分散”的问题；本地部署小模型还能兼顾隐私。
- **接入分词与词性**（若允许第三方依赖）：用 jieba 等做词级 TextRank，关键词质量会明显提升。
- **扩充评测集**：增加文本数量、多人标注、加入 ROUGE-L 与人工可读性打分，让指标更可信。
